# v1.8.3 数量口径修复验证

用户要求：6 个关键词、双平台、每平台 50 条，目标为 600 条主帖，每关键词 100 条。

根因：前端选项和采集模型默认 per_platform，按顺序从平台总额度扣减；第一个关键词达到 50 条后其他关键词目标变为 0。定时入口缺省回退虽为 per_keyword，但前端显式提交 per_platform 覆盖了回退。

改动：统一默认 per_keyword；保留明确选择的高级口径；保存时明确记录口径。启动时一次性迁移旧搜索定时配置，标记和配置同事务提交，原记录 spec 不变。目标预览显示关键词、平台、条数的公式并过滤重复关键词及空行。

验证：
- 完整测试 265 passed、8 deselected，33.56 秒，日志 /private/tmp/v183-tests.log。
- 五项浏览器检查通过，包含 1,400 次导航，日志 /private/tmp/v183-ui.log。
- 引擎边界验证 12 组各 50 条，共 600 条，重开续抓无重复请求；历史去重等现有回归同时通过。
- 数据库升级覆盖 per_platform、缺省、per_keyword、total、URL 任务以及二次启动保留主动修改；历史记录继续为 100 条。
- 首轮沙箱内测试有 4 项因禁止 localhost 监听/启动 Chromium 失败；获准在沙箱外完整重跑后全部通过。

限制：平台响应采用模拟数据，浏览器检查使用真实本机 Chromium。无真实账号在线抓取、无用户 Win11 WebView2 实机验证。评论阶段跨日运行尚缺用户日志；不将该问题列为本版本已修复项。旧运行不会被强制更改为 600 条，升级后需启动新一轮。

发布：Windows/macOS 测试、打包、自检由标签触发的 GitHub Actions 执行；正式状态以线上发布记录为准。
