# 图片采集流水线与跨任务平台调度

状态：v1.9.4 发布记录，2026-10-28。没有替换正在运行的客户端或修改其数据库。

## 行为

- 所有关键词、所有平台的主帖搜索结束后才开始评论。每个阶段内 X 和 Reddit 独立执行，不再因等待 X 而阻塞同阶段可执行的 Reddit 工作。旧版总量共享（count_scope=total）在主帖阶段保留按平台顺序分配剩余额度，避免并行超额；默认每关键词每平台模式不受此限制。
- 进程共享的平台门闸仍是同平台一个批次、不同平台最多两个；评论批次仍最多两个主帖。跨线程等待使用 FIFO 票据，取消会清理票据；平台退避不变，不增加同平台的请求并发。
- 仅图片模式对 X 提取评论 ID、原生图片地址和来源时间，不展开/提取正文；无图条目只参与当前遍历去重和停滞判断。Reddit 仍递归检查无图父评论及 morechildren，图片提取只执行一次，正文不进入保存记录。
- 保留主帖元信息和带图评论，恢复旧图片任务时移除无图评论及正文；保留已发现图片和来源关系。图片检查按当前可访问分页/页面判断，不为平台评论计数差异补齐文本。达到扫描上限、访问异常、翻页未结束等仍为部分完成。
- 发现新图片后唤醒两个有界下载 worker；合并重复唤醒，已有图片不在同次执行内反复下载。评论检查和图片下载并行；结束前等待下载收尾，取消时先等待下载与平台 worker 退出，再发布中断状态。
- X 条件等待覆盖普通滚动、停滞额外等待和“更多回复”后的等待，新增内容提前到达即可继续。最短请求间隔和原最大等待时限保留。
- 界面只把图片作为图片任务成果，显示配图检查的主帖状态与下载计数，不显示评论条数和总行数。等待平台时隙有单独说明。

## 验证

- 全量回归、浏览器检查、压力测试的最终结果见 validation.json。
- 新增场景：长段无图评论之后的图片、无图 Reddit 父节点的深层图片、折叠评论图片、评论广告计数不一致、无图扫描达到上限不能误报完成、下载早于评论结束、取消下载恢复、双任务主帖/评论平台独立推进、跨任务来源隔离、FIFO 重抢与取消清理、三线程同平台互斥。
- 真实 Chromium 模拟虚拟列表：文本 200 条；图片模式检查 200 条仅保留 10 条带图评论；未发生图片缺失或页面残留。该测试不连接真实平台。
- 压测包含 600 主帖/1200 图片、并发快照导出、HTTP 断连、两个全局下载连接上限以及已有评论与图片恢复压力场景。

## 尚未解决的边界

- 任务只配置单平台，或另一平台访问失败时，跨平台并行不会提供额外吞吐。FIFO 仍需等待已发出的批次和平台退避，不能抢断正在执行的请求。
- 同平台评论仍为每批两个主帖，短帖可能等待同批难帖；未在本次改为滑动 worker 池。
- 尚未持久化评论分页游标或跨轮保留页面位置；深帖补抓仍可能重复加载旧前缀。只保留图片不意味着可以跳过无图页面。
- X 评论来源归属仍受既有 DOM 提取路径约束，本次不宣称已解决推荐内容混入的问题。
- Reddit 403、平台限流、隐藏/删除或权限受限内容不能靠排程修复；不承诺真实任务固定提速比例或永不报错。
