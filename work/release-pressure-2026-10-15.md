# v1.8.0 发布压力测试与验证记录

日期：2026-10-15。环境：本地 macOS / Python 3.12 / Playwright Chromium。所有账号、平台返回和数据库均隔离，未对真实 X/Reddit 账号发起压力流量。

## 发现与修复

初始压力场景 5 项中 2 项失败：24 个同时提交创建了 24 个后台线程；模拟慢 Excel 生成阻塞 API 事件循环。修复后通过。

- 手动采集在创建记录/线程前检查 8 个在途任务上限，超限 429；定时任务在创建抓取线程前由 4 个并发槽排队。
- 大文件生成移到线程，采集下载同时限制为 2 份；历史列表查询不占 API 事件循环。
- 恢复占用与检查点重置顺序调整，40 个重复恢复请求只启动 1 个，其余 409，不修改在途检查点。
- 完成结果缓存保留 3 份且合计最多 64 MB。超限只释放内存中的文件内容，可从持久化记录重建。移除旧审核遗留的全文缓存。
- Reddit 的扁平评论与 X 的嵌套评论按各自真实结构测试，补齐导出 comment_id 及定时转换后的评论 ID。

## 持续压力循环

同一 Python 进程连续执行 10 轮压力套件，100 个场景全部通过，总耗时 151.0 秒；进程累计峰值 RSS 462.3 MB，后续多轮峰值保持稳定。测试每轮结束执行垃圾回收；该结果不是多日无泄漏证明。

## 发布门槛

Windows 与 macOS 发布流水线执行完整测试（含上述压力场景）以及四个真实浏览器脚本。打包后运行 `--self-test REPORT.json`，以独立临时数据目录验证启动、数据库、静态页面、审核接口、检查点、CSV/XLSX、tzdata、平台模块导入与随包 Chromium，并核对版本号。任一步失败则不发布。
