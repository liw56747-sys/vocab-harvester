# 评论抓取与补抓可靠性修复验证

日期：2026-10-16（Asia/Shanghai）  
基线：v1.8.1；本记录描述 v1.8.2 的发布前本地验证。Windows/macOS 发布构建与自检由 GitHub Actions 单独执行。

## 问题与改动

用户提供的导出包含 100 个主帖、2,902 行评论，75 个主帖评论未完成。Reddit 的 37 个请求返回 403，另 1 个异常文本为空；其余 12 个只是搜索返回评论数为零而被直接标记完成。X 存在页面加载超时、连接断开、未加载和数量缺口。这些证据不能证明所有失败都是 Cookie 过期，也不能推断平台显示的回复都可访问。

1. Reddit：统一搜索与评论的请求头；沿用搜索得到的会话 Cookie，恢复时优先使用记录中的可用端点，评论成功后沿用最新可用端点。www/old 两个公开端点的回退用于首屏、morechildren 和深层会话，401/429 不轮换端点。三个主帖在两个端点连续被拒绝后暂停本轮后续请求，避免重复请求风暴。Cookie 只在内存使用，不写入采集记录。
2. Reddit 完成判定：零评论也请求接口核验，旧零评论记录可在“只补评论”时重新核验；有显示数量缺口、未返回折叠评论或接口错误时保留未完成标记。空异常字符串保存异常类型。
3. X：评论等待与搜索分开，初始等待 45 秒，无新增时增加等待并检查页面异常；重试保留旧评论并按 ID 合并，已经取得部分评论后仍可有限重试。删除/不可访问、登录失效、拒绝访问及限流不盲目重试，数量缺口不误报完整。重试没有新进展时结束本轮，保留缺口。
4. 进度：新增小型持久化汇总、原因分类、本轮新增数量及空评论核验数量。轮询不读取完整评论、不生成 Excel；历史记录与汇总区自动刷新。显示运行中、保存中、本轮结束仍有缺口、可访问评论处理完成；中断和失败独立展示。
5. 界面：网络刷新失败会说明任务可能仍在运行并自动重试；关闭面板、离开页面和隐藏窗口时停止后续轮询。防止重复启动、重复导出，以及旧刷新响应覆盖刚启动的任务。下载明确是请求时的保存快照。
6. 导出：添加评论原因、尝试次数和空评论核验字段，X 评论填充独立 comment_id；保留正文和已有评论。

## 完成判断

- “本轮结束”只说明后台本轮工作已结束，不说明所有评论齐全。
- 最新汇总主帖缺口为 0、待补抓为 0，且本轮状态为完成，表示程序未发现可访问评论的剩余缺口。
- 不可访问、删除、隐藏及权限限制仍作为明确缺口保留，不为凑出“完成”而忽略。
- 如果平台没有可靠总数或不暴露完整评论树，程序不能证明全部历史评论均已获取。

## 自动化验证

最终完整测试：263 passed，8 deselected，35.22 秒。排除项为显式标记需手动运行的集成/交互测试；完整套件包含现有本机 HTTP 服务压力测试和 Chromium 会话回归。

新增故障测试覆盖：

- Reddit 搜索端点回退后的会话与评论端点复用、更多评论回退、零评论核验、空异常、持续 403 请求上限、数量缺口。
- X 部分评论失败后重试合并、无新增重试停止、404 不可访问、历史评论纳入单帖限制及页面清理。
- 进度查询不生成导出、不重读完整内容；旧汇总初始化不能覆盖新进度。

连续压力测试：同一 Python 进程运行 10 轮，每轮 14 个场景，合计 140 个场景全部通过，耗时 217.66 秒。每轮包含：

- 100 个主帖、3,000 条已有评论，75 个待补抓主帖；首轮新增 700 条，剩余 5 个明确缺口；重新打开数据库后只补这 5 个，再新增 50 条。再次补抓新增为 0，已有 3,750 条评论全部保留。
- 20 并发下执行 300 次汇总读取，同时写入 100 次进度；每个响应小于 4 KiB，已处理与待处理数量始终对齐，无 Excel 生成，SQLite 完整性检查通过。
- 补抓中途取消，首个新评论检查点和历史 3,000 条评论在重开数据库后全部存在。
- 现有并发检查点、大数据导出、跨事件循环抓取队列、双平台评论恢复、重复启动防护和缓存场景。

每轮收尾均为 1 个线程、4 个文件描述符。进程最高 RSS 依次为 451.8、525.0、546.7、580.5、597.4、597.4、597.4、597.4、597.4、615.4 MiB。RSS 是进程历史峰值，不是每轮结束时的驻留内存；末轮继续升高，因此此记录不能证明长期无内存泄漏。

## 浏览器界面验证

五项 Playwright 实际 Chromium 检查通过：采集参数与恢复控制、汇总与下载、1,400 次导航切换、更新入口、补抓进度。没有未捕获页面 JS 错误。

补抓场景额外验证：旧结果立即替换为运行中，自动更新为有缺口或完成；本轮新增数/原因正确；503 后恢复；重复点击只提交一次；刷新与启动重叠不会丢失后续轮询；关闭面板后不再发起请求。最终界面竞态防护增加后，补抓专用浏览器检查再次通过，包含刷新与导出重叠时防重复和按钮恢复。

## 边界

- 使用临时数据库、模拟平台响应和本机 HTTP 服务，不对真实社交平台施加压力，不改动用户原 CSV 或生产采集记录。
- 本记录中的测试在本机 macOS 执行；未在用户 Win11/WebView2 实机验证或安装新版客户端。正式安装包另由发布流水线构建和自检。
- 平台拒绝访问、隐藏评论或网络故障仍可能发生。本次验证重点是可恢复、保留数据和状态准确，不承诺所有真实平台评论可取或未来绝无异常。
