# X 搜索加载失败诊断（2026-10-08）

## 证据与结论

- 用户报告 v1.7.9 手动 X 搜索与定时双平台抓取均无法取得 X 内容；界面显示 0 条。
- 本机应用日志：10:22 起的定时搜索与 10:51、10:53 的手动搜索均等待 `article[data-testid="tweet"]` 超时，刷新后仍没有帖子元素。
- 应用保存的 10:23:03、10:52:42 截图显示 X 账号导航已出现，但主搜索区域一直加载。由此只能判断未加载成功，不能认定真实搜索结果为空或账号完全有效。
- 使用安装包所带 Chromium、已配置账号与代理进行有限只读诊断：未开启加速拦截，仍没有帖子；捕获 `abs.twimg.com` 多个 JavaScript 请求失败，错误为 `net::ERR_HTTP2_PING_FAILED`。说明此次现场测试存在 X 静态资源的传输故障，不是仅屏蔽图片导致。
- 相同诊断仅禁用 HTTP/2 后，未观察到同一网络错误，但等待 30 秒后仍无帖子；不能声称该开关已修复抓取，也不能单独锁定代理软件、上游节点或账号为唯一根因。
- 历史日志在 9 月 30 日存在成功获取 50 条 X 主帖的记录；10 月 8 日启动日志确认版本为 1.7.9。未读取到足够信息判断首次故障时间。

## 代码确认的问题

- 手动搜索与定时搜索复用 `TwitterCookieFetcher.search_tweets` / `_scrape_search`，因此同一页面加载故障会影响两个入口。
- `src/crawlers/twitter_url.py::_scrape_search` 在两次等待失败后，无论明确“没有结果”还是页面异常，都返回 `[]`。上层因此显示“无搜索结果”，掩盖加载失败。
- 请求拦截器 `src/crawlers/browser_manager.py::apply_request_interceptors` 为所有请求覆盖 `x-csrf-token`，没有按站点/API 范围收敛；Cookie 中 `ct0` 被设置为 HttpOnly，浏览器 UA 固定为 Chrome 120。这些值得做独立兼容验证，但本次未证明它们就是此故障的直接原因。

## 后续处理

1. 使用同一电脑、账号、代理，在普通浏览器搜索同一关键词，区分账号/链路故障与嵌入抓取环境问题；用户已确认本机 Chrome 同账号可以正常搜索。
2. 若普通浏览器也失败，优先检查代理中 `x.com` 与 `abs.twimg.com` 等 X 资源域名的连通性和路由，再测试稳定连接；不要仅因 0 条就反复重跑定时任务。
3. 若普通浏览器正常，继续对照程序浏览器网络失败、HTTP 状态、Cookie 更新与页面脚本错误。仅保存诊断元数据，不输出 Cookie 或请求凭据。
4. 代码应区分明确空结果与加载失败；汇总页保留简短原因，具体诊断写日志。不要仅延长超时或禁用 HTTP/2 就宣称修复完成。

本次未修改抓取实现、用户配置或数据库，未推送或发布新版。诊断浏览器会话已关闭。

## 同日继续诊断：Chrome 正常后的对照

- 用户确认本机 Chrome 使用同一个账号能正常显示网站与搜索结果。
- 使用程序数据库中保存的账号、代理，在独立 Chrome 154 临时上下文搜索 weather：SearchTimeline HTTP 200，DOM 出现 5 条帖子，约 33 秒。未读取日常 Chrome 的个人资料。
- 使用安装包内置 headless shell，浏览器默认 UA、ct0 非 HttpOnly、不做请求拦截：同样 HTTP 200，DOM 出现 5 条帖子，约 30 秒。不能归因于浏览器内核必然不兼容。
- 使用程序的 Chrome 120 UA、HttpOnly ct0、加速屏蔽、固定旧 ct0 请求头（诊断出于凭据边界限制，只对 X 自身域名注入）：复现 SearchTimeline HTTP 403 和错误码 353。
- 仅记录布尔比较：403 请求的 x-csrf-token 与实际 Cookie 中 ct0 不同，且实际 Cookie 已不同于导入值。确认“页面更新会话校验值、拦截器仍强制覆盖旧值”是可复现故障。
- 对照不记录 Cookie、请求头原文、响应正文或帖子内容；临时浏览器均在测试后关闭。
- 修复方向：让 X 网页使用当前 Cookie 生成请求头，避免固定导入值覆盖；ct0 应允许网页读取，auth_token 保持 HttpOnly；将明确无结果与加载/接口失败区分。不能只建议更新 Cookie 或关闭加速，因为两个模式都执行固定值覆盖。
- 已读现有测试：test_speed_mode_keeps_layout_and_comment_requests 断言所有放行请求均注入固定值；没有覆盖服务器轮换 ct0，因此该测试无法发现本问题。
- 最后对照保持安装包内核、Chrome 120 UA 和加速屏蔽，去掉固定请求头覆盖并允许页面读取 ct0：SearchTimeline HTTP 200、校验头与 Cookie 一致、DOM 出现 5 条帖子（约 31 秒）。此前一次 25 秒等待因脚本未加载完未取得结果，因此仍需兼顾加载等待与网络诊断。
- 本轮仅验证原因及修复方向，未改产品实现、未替换已安装客户端、未发布。5 条是等待页面首次出现帖子后的 DOM 计数，不代表已验证批量数量、评论或定时任务全流程。
