# P0/P1 采集改造与下一阶段图文审核方案

日期：2026-10-15。范围：本地实现与验证；本文件不表示已发布新安装包。

## 已实现的采集能力

### 统一执行与数量口径

单关键词、多关键词、X 主页和定时任务接入 `src/collection/`。新建搜索默认按每平台合计的去重主帖计算；还可选择每关键词/每平台分别计算，或整个任务合计。整个任务合计按所选平台顺序填充，不保证均匀分配。评论单独计数。X 主页按每用户计算。

跨关键词、时间分段和不同排序的结果用平台、类型、帖子/评论 ID 去重。每关键词模式下，已经在其他关键词计数的帖子不再次占用目标；目标、实际数量与缺口明确显示。旧定时任务未配置数量口径时保留原每关键词语义。

### 落盘、续抓与独立评论队列

本地数据目录新增 `collection.db`，独立于既有 `vocab.db`。每次有效页面快照提交帖子与评论，保存任务参数、分段位置、扫描数量、评论状态。此库不保存 Cookie、代理凭据或模型密钥。恢复读取当前账号配置。

重启后进入“采集记录、断点续抓与评论补抓”，选择汇总/下载、继续补抓或只补评论。不会未经用户选择立即重放全部历史任务。续抓沿用该轮保存的参数；修改范围需新建一轮。

平台游标可能绑定旧会话，因此恢复会重新打开未完成分段、扩大查询前缀并与已落盘 ID 去重，不承诺直接复用已失效的平台游标。一次分段最多扫描 4 轮、单次请求上限 10,000；不足时报告缺口/扫描上限，可缩小时间范围后补抓，不宣称一定取满。

主帖搜索与评论分开执行。只补评论不会重新搜索主帖，已完成的评论父帖跳过，失败/部分完成父帖重试；新旧评论按 ID 合并，保留已保存内容。评论分页/折叠/数量保护上限仍存在，其警告与待补抓数保留。

### 可用性检查与限速

“检查账号配置与搜索可用性”执行每平台最多 1 条主帖的轻量搜索，不抓评论；正常空搜索与请求失败分开处理。此检查不是 Cookie 有效期保证，也不是数量/评论完整性的证明。

登录/配置错误、拒绝访问、限流、网络异常、平台临时故障和未知错误分类处理。临时错误有限重试，鉴权和访问权限错误不盲目重试；429 后退避。所有入口共用进程内平台占用控制，同平台最多一项重任务、总计最多两个平台任务；耗时或失败后增加后续等待，成功后逐步恢复。原批量接口的高并发参数不再提高同平台并发。

### 日期范围、关键词组合、增量与回查

支持 UTC 起止日期（结束日不含当天）、按天数分段、额外关键词组合，以及不足时切换热门/最新。X 支持语言代码过滤。Reddit 在可访问搜索结果中筛选日期，不保证平台提供任意历史区间搜索；语言条件仅作用于 X。

定时任务可开启增量模式：读取前次成功采集水位，加回查窗口生成下一轮范围，并跳过已保存主帖；最近窗口内发布的旧帖可单独更新评论。新增主帖与回查旧帖分开统计。更早发布的旧帖不自动回查，可从对应采集记录手动补评论。固定日期范围优先于自动生成范围。

### 定时任务与旧任务兼容

新任务使用标准 Cron 星期规则（0/7=周日、3=周三），提供星期/时间选择器、IANA 时区、可读说明和下次执行时间；保存前校验表达式和采集参数。表达式同时限制“日”和“周”时采用标准 Cron 的 OR 语义。

旧任务保留 APScheduler 的既有星期含义（0=周一、3=周四）并明确标记，避免升级静默改变执行日。使用星期选择器重新确认后转为标准规则。Windows 安装包显式携带 tzdata。

保存下次应执行时间。重启/唤醒后记录漏跑，默认等待下一次；可选择合并补跑一次，不集中重放所有错过的轮次。同一任务仍防止重入。客户端退出或电脑睡眠期间不能实际抓取，补跑发生在恢复运行后。首次升级前没有持久化应执行时间的漏跑无法追溯恢复。

## 下一阶段：文本与图片联合审核（方案，尚未实现）

### 当前接口的实际限制

按后续要求，旧版内置模型审核与模拟审核已移除，只保留 `src/adapter/base.py` 中立适配器以及 `/api/audit/*` 提交、轮询和状态接口。应用采集/定时不再调用审核，旧模型配置也不会恢复审核。外部实现尚未接入，未接入时接口明确返回 503。

具体协议与兼容策略见 `work/audit-interface-2026-10-15.md`。现有候选词输出格式继续兼容词库，但尚无图片候选库；后续图文方案不属于本次已完成功能。

本次已停止加速模式主动删除媒体 URL，并在定时任务的原始元数据中保留媒体来源。这只是后续接入基础，尚未下载原图、做 OCR、调用视觉模型或生成拦截图。

### 推荐链路

1. **采集统一内容包**：以平台 + 类型 + 内容 ID 定位帖子/评论，保留父帖关系、正文、发布时间、命中关键词和图片顺序；一帖多图不能拆散后丢失关联。
2. **独立下载队列**：主帖完成后下载允许类型的实际图片，校验响应类型、字节数与解码像素数，限制并发并重试；解析相对链接、失效链接和原图/缩略图。下载结果持久化，不把短时有效的远程 URL 当作唯一资产。
3. **资产落库与去重**：保存本地路径或对象存储键、来源 URL、尺寸、MIME、SHA-256；SHA-256 用于完全相同文件去重，pHash 用于视觉近似检索。视觉向量用于候选召回，不直接替代拦截规则。
4. **文字/OCR/视觉分支**：正文走文本审核；图片走 OCR 与视觉审核。OCR 文本记录所属图片和位置。纯文字帖子不等待图片；图片失败记录不完整状态，不能标为整条审核完成。
5. **图文联合判定**：把同一条内容的正文、图片及 OCR 证据一起交给支持视觉的模型或外部图文审核工作流。限制每次图片数量并按同一 content_id 分批，最后汇总；返回明确的内容级结论及资产级证据。
6. **候选词/图片规则生成**：从审核证据提取最小词语/短语候选；对图片生成候选资产规则，而不是让模型凭空创造“拦截图”。带上下文才成立的风险，输出上下文规则，避免误当作独立词语或独立图片全局拦截。
7. **验证、审核与版本发布**：字段校验、来源证据可追溯、去重与正常样本误命中评估后，候选进入待审核库。批准后按版本导出；记录撤销、失效日期、规则版本和工作流版本。

### 内容包建议

```json
{
  "content_id": "twitter:post:123",
  "parent_content_id": null,
  "text": "原始正文",
  "published_at": "2026-10-15T07:00:00Z",
  "images": [
    {"asset_id": "sha256:...", "storage_key": "images/...jpg", "order": 0,
     "source_url": "https://...", "sha256": "...", "phash": "...",
     "ocr": [{"text": "图中文字", "bbox": [0, 0, 100, 50]}]}
  ],
  "collection_status": {"text": "complete", "images": "complete"}
}
```

传给外部工作流时根据其能力使用短时授权 URL 或文件上传；密钥不进入内容包。审核输入不携带无关账号凭据。原帖正文、OCR 和图片中的指令均为待审核材料，不作为系统指令执行。

### 审核输出与两个候选库

| 字段/对象 | 词候选 | 图片候选 |
| --- | --- | --- |
| 身份 | candidate_id、原词与归一化词 | candidate_id、asset_id、SHA-256 |
| 证据 | 原文片段，或 OCR 片段 + 图片位置 | 原图/裁剪图与区域，关联正文/OCR |
| 匹配方式 | exact / contains / context_only；regex 必须另行校验 | exact_hash / perceptual_hash / context_required |
| 风险定义 | 分类、适用场景、理由、置信度 | 分类、适用场景、理由、置信度 |
| 生命周期 | pending / approved / rejected / expired | pending / approved / rejected / expired |
| 可追溯性 | content_id、workflow_version、规则版本、审核记录 | 同左，另存相似度阈值与校准样本 |

“可入库”应指字段完整、证据有效、可去重且规则可执行；不等同于未经审核立即加入线上拦截规则。

词库可继续扩展现有 `vocabulary`。图片建议新增 `media_assets`（文件事实）、`image_candidates`（候选判断）与 `review_runs`（图文审核记录），不要把图片硬塞进 word 字段。

### 工作流接入路径

优先保留现有 Adapter 接口，新增 `submit_content_bundle` 与结构化结果，旧文本调用保持兼容。有两种落地方式：

- **当前模型接口扩展**：增加支持图片输入的模型配置，明确用图文消息格式传输图片；服务端用 schema 校验结构化结果。适合先打通端到端流程。
- **外部审核工作流**：另加 HTTP 适配器，按工作流的文件上传、请求字段、回调或轮询协议接入；由系统做幂等投递、超时重试和结果落库。协议未确认前不假设文本接口能直接接收图片。

推荐先实现“正文 + 静态图片 → 候选词库/候选图库 → 人工审核 → JSON/CSV 与图片包导出”；再做 pHash 近似匹配阈值校准和按内容场景的自动批准。GIF、视频抽帧与向量检索可后续扩展，不与第一版混在一起。

### 图文阶段验收用例

一帖多图、文字安全但图片违规、图片安全但组合语境违规、OCR 规避字、图片失败重试、重复图片跨帖使用、同图配不同正文、裁剪/加字/压缩变体、纯文字帖子、结构化输出错误、工作流超时重复回调、批准后撤销。

界面继续显示汇总：主帖/评论数量，图片发现/下载/失败数量，文本/图片/联合审核完成数，候选词/图片数量与待审核数。原文和原图仅在明确的审核/证据查看界面按需打开，不放进抓取结果页。
